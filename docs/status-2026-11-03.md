## Where the frame goes (run 26, ms/frame avg)

The top-level buckets add up to wall time (61.4 against 61.2 measured):

| Bucket | ms | What it is |
| --- | --- | --- |
| render | 39.2 | the render hook, split below |
| ↳ g2dread | **22.5** | CPU copy of the two GPU-composed 2D screens back from mapped GL memory (`eidos_gl2d_pixels`, plat_gl2d.c), about 400 KB a frame |
| ↳ main2d | 8.8 | CPU work that prepares the GPU 2D export: VRAM copies, layer and export repack, OBJ poses. The per-pixel CPU compose is already skipped. |
| ↳ ui | 6.0 | `boot_ui_frame`. The g3d bucket (6.0) holds it, so real 3D time is about 0. |
| ↳ boot3d | 1.9 | |
| game | 10.0 | the game between frames (ARM9/ARM7/OS); geom 8.2 is inside it |
| audio | 4.2 | |
| present | 4.0 | |
| step | 3.4 | |
| pump | 0.7 | |

Read off this table:
- The 3D renderer is not the bottleneck at this spot. fix-ts Phase 2 (3D readback) would save about 0.
- **g2dread is the biggest item**, and it is CPU time, not a GPU wait (run 27).
  About 18 MB/s points at reads from uncached or write-combined mapped memory,
  plus a second full copy in the wasm `glMapBuffer` bridge (tools/wasm_gl_imports.py).
- **The UI reads those pixels every frame on the field**, so they can't simply be skipped:
  - `recipe_field.c` `lower_only_match` checks for a dark top screen and a busy bottom screen.
  - `ui.c` `flat_screen` checks for a white flash.
  - Full-screen readers are menu recipes only: bag, Pokédex, PC, endings, title.
- Swap fps understates game speed in paced runs. The profiler's game-frame line is the number to trust.

### Merge notes

- `HOST_MOBILE` (`host/main.c`) includes the Switch. 0.2.0 phone code under it has been fenced off the Switch:
  - `EIDOS_TOUCH_DEVICE` and `EIDOS_GL_ES`. `EIDOS_GL_ES` brings the 720-row cap and would have held docked below 1080p.
  - `host_pick_rom`: the Switch keeps `bw_pick_rom`.
  - `host_ios_view_setup`.
- 0.2.0's `rows_3d()`/`EIDOS_3D_ROWS` (platform.c) and the ES-only AA skip (`g->es`) never turn on for the Switch.
- The merge moved the aletheia pin to e3c8c25. The shared `src/aletheia` checkout is now at that revision (it was 828fe07).
- AGENTS.md §3 says to keep integration current by merging main, not rebasing. Integration was merged; only local topic branches were rebased.

## Build setup change

- Builds are now native macOS: devkitPro at `/opt/devkitpro` (devkitA64 r30, **GCC 16.1.0**, binutils 2.46).
  The Docker image had r29.2, GCC 15.2.0 and binutils 2.45.1. libnx 4.12.0, newlib and switch-tools are the same.
- GCC 15.2 can't be installed from pacman: the repo serves only current packages, and direct package URLs return 403.
  Pinning it means building devkitPro's buildscripts at r29.2, or installing old `.pkg.tar.zst` files.
  Runs 25–27 ran on 16.1 without a crash.
- Native NRO: `DEVKITPRO=/opt/devkitpro`, PATH with `devkitA64/bin` and `tools/bin`, then
  `python3 switch/build.py --module <module wasm> --build-dir <dir> --mesa-prefix
  ~/.cache/eidos/mesa-switch/16732f6…/mesa-install/opt/devkitpro/portlibs/switch --parts 96`.
  - A full NRO takes about 9 min; a host-only rebuild takes about 12 s.
  - The Mesa SDK is the cached static prefix and isn't rebuilt.
- **engine/ and demo/ code is in the wasm module.** Rebuild the module of the branch you're building before the NRO.
  The first diag3 build used the base module and had none of its changes (caught before it was sent).
- nxlink: `/opt/devkitpro/tools/bin/nxlink -s -a <switch ip> <nro>`, sent to the hbmenu netloader.
- `out/BUILD.md` still describes the Docker build.
