# Run 42 — orphan-on-respec + first-upload-through (fix-r6 tip 5cc43b0+)

Why: run 40-41 hitches showed multi-second stalls inside the 3D
texture upload loop on new scenes. Mechanism: re-spec with data
makes a backed-up driver wait for the store it replaces. Fix:
orphan first (NULL TexImage hands the driver a fresh store, no
wait), then fill with SubData. Budget stays as backstop (2MB/frame,
serial held until done). New slots get a 1x1 black TexImage at
creation (defined content, brief pop-in beats garbage). Same-size
SubData path untouched (works today).

Also fixes a real bug in the first budget version: oversize single
textures (>2MB) could never upload (need > budget forever). First
upload of each frame now always goes through.
